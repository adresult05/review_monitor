# 고객사 리뷰 모니터링 시스템

카카오맵 / 구글맵 / 네이버 플레이스에 올라오는 신규 리뷰를 매일 아침 자동으로 수집하고,
부정 리뷰(별점 낮음 또는 AI 감정분석 결과 부정)만 걸러서 Streamlit 대시보드 접속 시
경고창으로 보여주는 시스템입니다.

기존에 쓰고 계신 Streamlit + gspread + GCP 서비스 계정 + GitHub Actions 크론 패턴을
그대로 재사용합니다. 새 인프라를 만들지 않고 기존 프로젝트에 파일만 추가하면 됩니다.

## 플랫폼별 최종 방식

| 플랫폼 | 방식 | 비용 | 확인 가능한 내용 |
|---|---|---|---|
| 카카오 | 리뷰 원문 API 스크래핑 (실제 테스트로 검증됨) | 무료 | 리뷰 원문, 별점, 작성자 |
| 네이버 | 공개 페이지에서 평점/리뷰수만 추출 (검증됨) | 무료 | 리뷰수/평균별점 변화만 (원문 X) |
| 구글 | **자동화하지 않음.** 담당자가 수기로 확인 | - | - |

**구글을 자동화하지 않기로 한 이유**: 무료 스크래핑을 실제로 테스트해봤는데,
구글맵 페이지는 완전한 JS 앱(SPA)이라 서버가 데이터를 미리 심어주지 않아
(네이버와 달리) 단순 페이지 요청으로는 아무 정보도 못 얻습니다. 남은 방법은
① 구글 검색 결과 페이지 스크래핑(캡차 위험 있음) 또는 ② 유료 Places API인데,
둘 다 리스크/비용 대비 실익이 낮다고 판단해 구글은 제외했습니다.

나중에 마음이 바뀌면 `collectors/google_reviews.py`(유료 API, 원문까지 확인 가능)를
다시 연결할 수 있습니다. 구조상 `daily_check.py`에 몇 줄만 추가하면 됩니다.

## 전체 흐름

```
[GitHub Actions, 매일 오전 KST 08:00]
        │
        ▼
  daily_check.py 실행
        │
        ├─ 고객사설정 시트에서 고객사별 URL/ID 읽기
        │
        ├─ collectors/google_reviews.py  → 구글 Places API로 리뷰 수집
        ├─ collectors/kakao_reviews.py   → 카카오맵 리뷰 스크래핑
        ├─ collectors/naver_reviews.py   → 네이버 플레이스 리뷰 스크래핑
        │
        ├─ 기존 리뷰마스터 시트와 대조 → 신규 리뷰만 추출
        │
        ├─ sentiment.py로 부정 여부 판단 (별점 + AI 감정분석)
        │
        └─ 리뷰마스터 시트에 신규 리뷰 append (status=신규)
                │
                ▼
   [Streamlit 앱 접속 시]
   streamlit_alert.py의 show_negative_review_alert() 호출
        │
        └─ status=신규 & is_negative=True 인 행을 모달 경고창으로 표시
           확인 버튼 클릭 시 status를 '확인됨'으로 업데이트
```

## Google Sheets 스키마

기존 서비스 계정(sheetsearch-bot)이 접근 가능한 스프레드시트에 탭 2개를 추가하세요.

### 탭 1. `고객사설정`

| 컬럼명 | 설명 | 예시 |
|---|---|---|
| 고객사명 | 표시용 이름 | OO정형외과 |
| 활성여부 | TRUE/FALSE | TRUE |
| 구글_PlaceID | 구글 Place ID | ChIJxxxxxxxx |
| 카카오_장소ID | 카카오맵 URL의 숫자 ID | 12345678 |
| 네이버_플레이스ID | 네이버플레이스 URL의 숫자 ID | 1234567890 |

- 구글 Place ID는 https://developers.google.com/maps/documentation/places/web-service/place-id 의
  Place ID Finder로 확인 가능합니다.
- 카카오/네이버 ID는 각 플레이스 URL 안의 숫자입니다.
  (예: `place.map.kakao.com/12345678` → `12345678`,
  `map.naver.com/p/entry/place/1234567890` → `1234567890`)

### 탭 2. `리뷰마스터`

| 컬럼명 | 설명 |
|---|---|
| 리뷰ID | 플랫폼+원본ID 조합, 중복 체크용 |
| 고객사명 | |
| 플랫폼 | 구글 / 카카오 / 네이버 |
| 별점 | 1~5 (네이버 알림 행은 비어있음, 아래 참고) |
| 리뷰내용 | 구글/카카오는 실제 리뷰 원문, 네이버는 변화 요약 텍스트 |
| 작성자 | |
| 작성일 | 수집 가능한 경우만 |
| 수집일시 | |
| is_negative | TRUE/FALSE |
| 판단근거 | 별점기준 / AI판단 / 네이버 리뷰수·별점 변화 감지 |
| status | 신규 / 확인됨 |

daily_check.py 최초 실행 시 탭이 없으면 자동 생성합니다.

### 탭 3. `네이버통계이력`

네이버는 리뷰 원문 수집이 캡차로 막혀 있어(README 하단 참고), 대신 매일 리뷰
총개수/평균별점 스냅샷을 날짜별로 쌓아둡니다. 이 표 자체가 "몇월 며칠에 리뷰가
몇 개였는지"에 대한 기록이라, 시트를 직접 열어봐도 히스토리를 확인할 수 있습니다.

| 컬럼명 | 설명 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 고객사명 | |
| 리뷰총개수 | 그 날짜 기준 네이버 플레이스 누적 방문자 리뷰 수 |
| 평균별점 | 그 날짜 기준 평균 별점 |

매일 실행 시 **가장 최근 이전 날짜의 기록과 비교**해서 알림을 만들기 때문에,
주말이나 공휴일로 며칠 실행이 비어도 (예: 금요일 기록 → 월요일 실행)
정상적으로 "그 사이 몇 건 늘었는지"를 비교합니다.

## 설치 순서

1. **패키지 설치**
   ```bash
   pip install gspread google-auth requests beautifulsoup4 anthropic
   ```

2. **환경변수 / GitHub Secrets 등록**
   - `GCP_SERVICE_ACCOUNT_JSON`: 기존 서비스 계정 키 (문자열로 저장)
   - `SPREADSHEET_ID`: 대상 스프레드시트 ID
   - `GOOGLE_PLACES_API_KEY`: GCP 콘솔에서 Places API (New) 활성화 후 발급
   - `ANTHROPIC_API_KEY`: AI 감정분석용 (Claude Haiku 사용, 비용 최소화)

3. **daily_check.py를 기존 GitHub Actions 워크플로에 추가**하거나
   `.github/workflows/daily_review_check.yml`을 그대로 복사

4. **기존 Streamlit 앱 어딘가(메인 페이지 최상단 등)에 추가**
   ```python
   from streamlit_alert import show_negative_review_alert
   show_negative_review_alert()
   ```

## 중요한 주의사항 (미리 알아두셔야 할 것)

- **구글**: 공식 API라 가장 안정적입니다. 다만 Places API(New)는 장소당 **최신 리뷰 최대 5개**까지만
  반환하고, 정렬 기준도 '최신순'이 아니라 '관련도순(most relevant)'입니다. 리뷰가 하루에 5개 넘게
  달리는 병원이 아니라면 문제 없지만, 참고해두세요. 또한 Google의 API 이용약관상 리뷰 원문을
  장기간 별도 DB에 캐싱하는 것에 제약이 있어, 리뷰마스터 시트에는 알림/추적 목적의 최소 정보만
  저장하도록 구성했습니다.

- **카카오**: 공식 리뷰 API가 없어 페이지 구조를 이용한 수집 방식입니다. 실제 테스트로
  `place-api.map.kakao.com`의 리뷰 엔드포인트를 확인해 정상 작동을 검증했습니다. 다만
  비공개 엔드포인트라 예고 없이 응답 구조가 바뀔 수 있습니다.

- **네이버**: 실제 테스트 결과, 리뷰 원문을 요청하는 API(GraphQL)는 네이버가 캡차로
  차단하는 것을 확인했습니다 (로그인 없는 익명 접속을 봇으로 판단). 이 부분은 계정
  접근 권한 없이는 우회하지 않는 것이 맞다고 판단해 다른 방식으로 전환했습니다:
  리뷰 페이지 HTML 자체에는 서버에서 렌더링된 리뷰 총개수/평균별점이 포함되어 있어
  (`avgRating`, `visitorReviewsTotal`), 이 값만 매일 스냅샷으로 쌓아서 전날 대비
  변화를 감지합니다. **리뷰 내용까지는 알 수 없고, "리뷰 수가 늘고 평균 별점이
  떨어졌다"는 신호만 잡아서 담당자가 직접 확인하도록 안내**하는 방식입니다.
  만약 나중에 고객사로부터 스마트플레이스 직원 권한을 받을 수 있게 되면, 로그인된
  세션 기반으로 리뷰 원문까지 가져오는 방식으로 업그레이드할 수 있습니다.

- **AI 감정분석 비용 절감 구조**: 모든 리뷰를 AI에 보내지 않습니다. 1) 별점 3점 이하는 바로
  부정으로 확정, 2) 4~5점인데 리뷰 내용에 부정 키워드(불친절, 실망, 부작용, 환불 등)가 포함된
  경우에만 AI 판단을 추가로 거칩니다. 이렇게 하면 호출 건수가 크게 줄어듭니다.
